# Useful 3D candidate timing

Extend the existing removable offline first-visual harness, not the application. No Vork implementation is copied.

A second fixture streams two differently coloured public gear parts plus a panel/camera through the real parser, validator, IPC and renderer. Its endpoint requires substantial pixel area and two-dimensional extent for both parts before step close. This is a reviewable candidate for usefulness, not automatic semantic acceptance. Record human acceptance and live-model target as unmeasured; no invented model timing.

Approaches considered: production instrumentation would change the live boundary without an authorized working model route; standalone screenshots duplicate capture infrastructure and omit streaming timing. Extending the existing harness preserves its one monotonic request clock, safety controls and 2D result.

Native WebGL must work under default security settings. Do not force unsafe software rendering, disable the sandbox, download dependencies, call a model or capture the user's display. A missing native renderer returns a structured unavailable result, null measurements, and non-success exit. Production code remains unchanged. A separate visual-quality branch owns general scene inspection.
